Most of what I build, I build with AI. These are the rules I've learned the hard way, in my own words where I wrote them down, and how my way of working has changed since March.

## Five rules

**1. Ask every design question first, in one batch.** Some characters for a game took three passes. I said: *"we could have done the characters in 1 pass not 3 passes just because you didn't ask enough questions."* Now I make the AI ask everything up front.

**2. Check the real output, not the tool's success message.** A tool said "success" while the file was wrong. I verify by reading the result back myself. It happened again with some thumbnails, where a matching count hid a shifted mapping.

**3. One thing at a time.** *"I told you just to do the map, not everything at once."* *"Let's work on one thing, perfect it, then move on."* For a game I made a ladder of milestones with a kill rule: if the first one isn't fun, stop.

**4. Play it before you build more.** One game had 18 fish, duels, boats and a tutorial, but I played it and wrote *"it all works… it's all buns."* The AI's own summary was "built but not proven". Reference screenshots and a quick playtest beat more systems.

**5. Usage and time are the real constraint, so stop early.** When I checked, the drain was long chats being re-read, not long replies. If a quick request needs installs or fails twice, I stop and look at the options instead of falling down a rabbit hole.

## Things I've said that stuck

- *"I don't want to forget anything we do, so every now and then make a thing you can read to never forget anything."* This is why I keep an [Obsidian Brain](../projects/obsidian-brain/).
- *"Cut out my work, like editing the video."* On automating my video workflow.
- *"We pretty much just need huge hooks, and we need better cliffhangers."*
- *"The script about the tree was awful."* I scrapped a finished video.
- *"I'm making the bag, so why is it making it? I build the models unless I say anything."* The AI does the tools around my work, not my work.
- *"Surely Notion can't be that hard to build."* It was [online](../projects/mynotion/) about an hour and twenty minutes later.
- *"I want it so you don't have to sign in but can still join a game from any device."*

## How my way of working changed

- **March to April: chat and paste.** Single HTML files made in a chat, uploaded by hand, bugs reported by pasting screenshots. My first rule: *"Test it before giving it to me, always."*
- **April to June: a growing pile.** One full-file rewrite used 58% of my limit, so I started asking for small edits. By late June I had so many projects that I built dashboards to keep track.
- **July to August: Claude Code.** The AI works directly inside my tools and I judge it against a reference screenshot. I started checking installs by their GitHub stars and asking for repeatable scripts instead of doing things by hand.
- **September: phases and scope.** After *"whenever I try and build it, it never goes the way"*, I moved to phased builds with strict prompts: context only, then build only this.
- **October: pipelines, numbers and teams.** I save notes at the end of every task, read my own channel stats, scrap work that isn't good enough, and tried to cut cost in order: local models, a free-model router, a cheaper helper.
- **November: building my own versions.** My own [Notion](../projects/mynotion/), my own [PC remote](../projects/pc-remote/), my own [clip tool](../projects/free-opus-clip/). I keep my own code and use the AI for the tools around it.
